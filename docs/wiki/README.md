# access-log-py Wiki

`access-log-py` (package `access_log_py`, version 0.1.0) is a **small Python library that adds JSON access logs to a Flask app**. Each request writes one JSON line to stdout. The line uses the same field names as BasharSoft's nginx JSON access log. So you can search Flask services next to nginx-fronted services in the log platform. It also sets an `X-Request-ID` on every response.

**How it serves Wuzzuf:** two Flask services install it from GitHub at tag `v0.1.0`:

- `cv-parser-algorithm` (`requirements.txt:31`, installed in `app/__init__.py:62-72`);
- `wuzzuf-talent` (`requirements.txt:36`, installed in `talent/config/__init__.py:108-117`).

We wrote this wiki from the source code (`main` at `1cffc82`). We didn't use the existing README/CHANGELOG/CLAUDE.md. Graphify generated the [code map](code-map/index.md).

> **Read [Known issues](known-issues.md) first.** Watch for `before_request` hooks that the app registers before `install()`. If one of them returns early (e.g. an auth check), the library still logs the request. But the record has no request id and a response time of ~0. `client_address` trusts the first `X-Forwarded-For` value, which clients can set.

## What's inside

| Path | What |
|---|---|
| `src/access_log_py/__init__.py` | Exports `install`, `SkipRule`, `default_skip_rules` |
| `src/access_log_py/flask_middleware.py` | `install()`: registers the Flask hooks and the logger |
| `src/access_log_py/formatter.py` | `JsonFormatter` and `build_payload()` (the record fields) |
| `src/access_log_py/filters.py` | `SkipRule` and the default rule that drops Kubernetes probes |
| `tests/test_flask_middleware.py` | 10 pytest tests |
| `pyproject.toml` | Hatchling build, needs Python ≥ 3.8 and `flask>=2.0`; `dev` extra adds `pytest` |
| `.github/workflows/test.yml` | GitHub Actions: `pip install -e ".[dev]"` and `pytest -v` on Python 3.8, 3.11, 3.12, on PRs and pushes to `main` |

## Running and testing

```bash
pip install -e ".[dev]"
pytest -v
```

Consumers add one line to `requirements.txt`:

```
access-log-py @ git+https://github.com/BasharSoft/access-log-py.git@v0.1.0
```

There is no PyPI release and no release workflow; a version is a git tag.
